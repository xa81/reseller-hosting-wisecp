# DNA Reseller Hosting

**Управляйте реселлерскими хостинг-аккаунтами cPanel и Plesk, предоставляемыми DomainNameAPI, из одного серверного модуля WiseCP.**

Один модуль, две панели. Тип панели вы не выбираете — модуль сам спрашивает сервер и запоминает,
какая панель ответила.

## ✨ Что умеет модуль

| Возможность | cPanel/WHM | Plesk |
|---|:---:|:---:|
| Проверка соединения и автоматическое определение панели | ✅ | ✅ |
| Создание аккаунта (повтор безопасен) | ✅ | ✅ |
| Приостановка / возобновление | ✅ | ✅ |
| Удаление | ✅ | ✅ *(с проверкой владения)* |
| Смена пароля | ✅ | ✅ |
| Смена пакета / тарифа (апгрейд и экран услуги) | ✅ | ✅ |
| Индикаторы диска и трафика в обзоре услуги | ✅ | ✅ |
| Использование диска и трафика для тарификации по потреблению | ✅ | ✅ |
| Вход в панель управления в один клик | ✅ | ✅ |

> 💡 **Создан для реселлерского хостинга DomainNameAPI.** Модуль предназначен для реселлерских
> аккаунтов cPanel/WHM и Plesk, которые предоставляет DomainNameAPI. Не требует root- или
> администраторского доступа; он работает с правами вашего реселлерского аккаунта DomainNameAPI, и
> каждый созданный им аккаунт учитывается в вашей квоте. Ещё нет реселлерского хостинг-аккаунта?
> Получите его на [dm.domainnameapi.com/hosting](https://dm.domainnameapi.com/hosting).

## 📋 Требования

- **WiseCP 5** или **WiseCP 3**, установленный на вашем сервере, с доступом администратора; у каждого свой пакет
- **PHP** 8.2 или новее на WiseCP 5, как того требует WiseCP 5; 7.4 – 8.4 на WiseCP 3
- Расширения PHP: те, которые WiseCP 5 уже требует, плюс `simplexml` (включено в стандартных сборках PHP)
- **Реселлерский хостинг-аккаунт DomainNameAPI**: cPanel/WHM (WHM API token) &nbsp;или&nbsp; Plesk
  (секретный ключ или пароль панели)
- Исходящий доступ с сервера WiseCP к серверу панели на API-порт панели

> ✅ Не создаётся ни одной таблицы в базе данных, не нужен cron и нет зависимостей composer.
> Ничего никуда не отправляется, кроме настроенного вами сервера панели.

## 🚀 Установка

### 1️⃣ Установите модуль

Каждый релиз содержит два пакета. Выберите тот, что подходит для вашей версии WiseCP:

| WiseCP | Пакет | Исходники в этом репозитории |
|---|---|---|
| **5.x** | `DNAHosting-WiseCP5-v2.x.x.zip` | `v5/coremio/` |
| **3.x** | `DNAHosting-WiseCP3-v1.x.x.zip` | `v3/coremio/` |

> ⚠️ **Пакеты не взаимозаменяемы.** В WiseCP 5 изменился контракт серверных модулей, поэтому модуль
> для WiseCP 3 не загружается в WiseCP 5, и наоборот.

Загрузите пакет через менеджер модулей или распакуйте его в корень вашей установки WiseCP.
Архив содержит полный путь, поэтому модуль окажется здесь:

```
wisecp/
└── coremio/
    └── modules/
        └── Servers/
            └── DNAHosting/     ← здесь
```

Шаги ниже относятся к **WiseCP 5**. В WiseCP 3 экраны называются иначе; см.
[WiseCP 3](#-что-полезно-знать) в разделе *Что полезно знать*.

### 2️⃣ Добавьте сервер

**Products → Hosting/Server → Server Settings → Add New Server.** В разделе **Server Automation Module**
на вкладке **Web Hosting** выберите **DNA Reseller Hosting** (находится в группе *Other*).

| Поле | Что указать |
|---|---|
| **Address** | Сервер панели. Оставьте переключатель **https://** включённым. Лучше указать имя хоста, которое покрывает сертификат панели; IP-адрес проходит проверку сертификата, только если сертификат покрывает этот IP |
| **Port** | Для cPanel уже подставлен `2087`. Для Plesk нажмите **Use Custom Port** и введите `8443` |
| **Verify SSL Certificate** | Оставьте включённым. Отключайте только для панели с самоподписанным сертификатом |
| **Username** | Ваше имя пользователя реселлера в этой панели |
| **Password** | **cPanel:** API-токен WHM, созданный от имени этого реселлера. **Plesk:** секретный ключ или пароль панели |
| **Hostname** | Имя хоста сервера панели; WiseCP также показывает его в записях серверов и услуг. Если это полное имя хоста, например `server.example.com`, модуль подключается к нему вместо **Address**, поэтому проверка сертификата работает, даже если в **Address** указан IP |

![Настройки сервера в WiseCP 5](https://raw.githubusercontent.com/domainreseller/reseller-hosting-wisecp/main/docs/images/v5-server-settings.png)

### 3️⃣ Проверьте соединение

Нажмите **Test Connection**. Зелёный результат подтверждает учётные данные и определённую панель;
при ошибке показывается HTTP-код или собственная ошибка панели. См. [Логи и диагностика](#-логи-и-диагностика).

### 4️⃣ Создайте группу серверов *(необязательно)*

Если серверов больше одного, создайте группу в **Server Groups** и привяжите продукт к группе, а не
к отдельному серверу.

> ⚠️ **Держите группу однородной по типу панели.** Список пакетов в форме продукта берётся с одного
> сервера. Если в группе смешаны cPanel и Plesk, выбранного имени может не оказаться в другой панели,
> и заказ, попавший туда, завершится ошибкой *пакет не найден*. Модуль хранит **имя** пакета, а не
> его id в панели, поэтому имя, существующее на всех серверах группы, работает на каждом из них.

### 5️⃣ Настройте продукт

Создайте хостинг-продукт и выберите **DNA Reseller Hosting** в **Module Assignment**. На вкладке
**Automation** продукта выберите **Single Server** (или группу серверов) и сервер. Затем модуль выводит
одно поле:

| Параметр | Значение |
|---|---|
| **Package / Plan** | Список, загружаемый с сервера в реальном времени; определённая панель указана в подписи, например *Package / Plan (cPanel / WHM)*. Если сервер недоступен, поле превращается в текстовое, а под ним выводится причина |

> 💡 **Не беспокойтесь о префиксе пакета в cPanel.** Пакет, который в панели значится как
> `reseller_basic`, можно указать как `basic`; модуль сам разрешает префикс.

> ℹ️ **Resource Limits** на той же вкладке в панель не передаются. Диск, трафик и другие лимиты
> аккаунта берутся из выбранного пакета или плана; WiseCP сообщает об этом и на экране услуги.

**Сохраните — модуль готов к работе.** 🎉

## 🔍 Логи и диагностика

Каждый запрос, который модуль отправляет в панель, и полученный ответ записываются в **журнал
модуля**, пока в WiseCP включено журналирование модулей. Каждая запись помечена вызовом панели,
например `createacct` или `webspace.add`.

> 🔐 Токен или пароль сервера, каждый пароль аккаунта, который модуль генерирует или меняет, и токены
> сессий единого входа маскируются как `***` **до того, как что-либо будет записано**, — и в запросе,
> и в ответе.

### Частые ошибки

| Симптом | Причина и решение |
|---|---|
| `HTTP 403` или *сервер ответил пользовательским API cPanel* | У реселлера, которому принадлежит токен, нет привилегии WHM для этого вызова. Выдайте привилегии на просмотр списка аккаунтов, создание, приостановку, удаление, смену пароля, смену пакета, просмотр списка пакетов, трафик и сессии в **WHM → Resellers → Edit Reseller's ACL List**, затем создайте токен **от имени этого реселлера** |
| Ошибка сертификата | Сертификат не покрывает указанный вами адрес. Укажите имя хоста, которое покрывает сертификат, или отключите **Verify SSL Certificate** для панели с самоподписанным сертификатом |
| Plesk **11003** | Секретный ключ выдан для другого IP. Создайте новый для адреса, с которого подключается WiseCP, или используйте пароль панели |
| *Отказано в целях безопасности: подписка … создана не этой услугой* | В Plesk модуль работает только с клиентами, которых он сам создал для данной услуги. Подписка была создана вручную или другой услугой |

## 🧩 Что полезно знать

<details>
<summary><b>Повторы безопасны</b></summary>

<br>

Очередь модулей WiseCP повторно запускает неудавшееся создание. Модуль сохраняет имя пользователя и
зашифрованный пароль до обращения к панели, поэтому при повторе они используются снова: аккаунт,
который был создан, но ответ о котором потерялся, подхватывается, а не завершается ошибкой
*уже существует*. Удаление аккаунта, которого уже нет, считается выполненным.

</details>

<details>
<summary><b>Различия панелей</b></summary>

<br>

- **Каждая операция в Plesk проходит проверку владения.** Клиент, создаваемый модулем, несёт номер
  услуги в качестве внешнего id, и эта метка проверяется перед любой операцией. Модуль никогда не
  сможет выполнить действие над подпиской, созданной вручную.
- **Смена домена действующей услуги Plesk** не передаётся в панель: подписка Plesk находится по
  своему домену, поэтому последующие операции сообщат, что подписки не существует. Переименуйте
  подписку и в Plesk. В cPanel аккаунт продолжает обслуживать старый домен, пока вы не измените его в
  панели.
- **Защита от дублирования домена.** Удаление отклоняется, пока тот же домен привязан к другой
  активной или приостановленной услуге на том же сервере.

</details>

<details>
<summary><b>Определение панели</b></summary>

<br>

Тип панели никогда не настраивается. При первом вызове модуль опрашивает сервер и на неделю
запоминает, какая панель ответила; **Test Connection** всегда опрашивает заново.

Порт определяет лишь то, какая панель пробуется **первой**: `8443` и `8880` сначала пробуют Plesk,
всё остальное — сначала cPanel. Неверная догадка замедляет определение, но не ломает его.
При определении модуль также отправляет указанные учётные данные на API-адрес другой панели на
**том же** сервере; ни к какому другому хосту он не обращается.

</details>

<details>
<summary><b>Учётные данные</b></summary>

<br>

Обе панели получают учётные данные из поля **Password**, которое WiseCP хранит в зашифрованном виде.
Поле **Access Hash** хранится открытым текстом, поэтому этот модуль его не предлагает и никогда не
читает. В Plesk модуль сначала пробует учётные данные как секретный ключ, а затем сам переходит на
логин и пароль.

</details>

<details>
<summary><b>WiseCP 3</b></summary>

<br>

Пакет для WiseCP 3 (`v3/coremio/`) предоставляет то же управление аккаунтами на собственных
экранах WiseCP 3:

1. **Products / Services → Hosting/Server → Shared Server Settings → Add New Shared Server.** Выберите
   `DNAHosting` в поле **Server Automation Type** и заполните **IP Address**, **Username**, **Password**
   (токен WHM API, секретный ключ Plesk или пароль Plesk), **Connect with SSL** и **Port**
   (`2087` для cPanel, `8443` для Plesk). Поле **Hostname** там — лишь метка; модуль подключается
   к **IP Address**. Нажмите **Test Connection**.
2. **Products / Services → Hosting/Server → Web Hosting Packages** → откройте пакет → вкладка **Module
   Settings**. Выберите сервер или группу; модуль покажет **Detected panel** и список **Package / Plan**.

Отличия от пакета для WiseCP 5:

- В WiseCP 3 нет переключателя проверки сертификата для серверных модулей. Если **Hostname**
  сервера — полное имя хоста, которое покрывает сертификат панели, пакет подключается к нему и
  проверяет сертификат; если указан только IP-адрес, он подключается к IP без проверки.
- В клиентской зоне отображаются использование диска и трафика и кнопка входа в панель; карточек
  обзора услуги из WiseCP 5 в WiseCP 3 нет.
- Смена домена работающей услуги в Plesk отклоняется, а не остаётся на усмотрение оператора.

</details>

<details>
<summary><b>Вне области применения</b></summary>

<br>

Инструменты управления почтой, базами данных и файлами, продажа реселлерских аккаунтов, импорт
существующих аккаунтов в WiseCP и кнопка *войти как администратор сервера*. Модуль хранит только
**реселлерские** учётные данные, никогда — root. Импорт исключён намеренно: импортированная подписка
Plesk не несла бы метку владения этого модуля, и каждая последующая операция над ней была бы
отклонена.

</details>
