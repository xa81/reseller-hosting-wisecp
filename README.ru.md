## Обзор

Модуль управляет обоими семействами панелей через одну серверную запись. Вы вводите IP, имя
реселлерского пользователя и один реквизит доступа; модуль действительно опрашивает сервер — это
настоящий вызов API, а не догадка — и запоминает, какая панель ответила.

| | |
|---|---|
| **Тип модуля** | Серверный модуль WiseCP (Servers) |
| **Имя папки** | `DNAHosting` |
| **Версия** | 1.0.0 |
| **Поддерживаемые панели** | cPanel/WHM, Plesk |
| **PHP** | 7.4 – 8.4 |
| **Языки интерфейса** | турецкий, английский (`lang/tr.php`, `lang/en.php`) |

## Требования

- Установленная на своём сервере **WiseCP**, к которой у вас есть доступ администратора
- PHP с включёнными расширениями **cURL** и **SimpleXML** (есть почти в любой сборке по умолчанию)
- Либо **реселлерский аккаунт cPanel/WHM** (с API-токеном WHM), либо **реселлерский аккаунт Plesk**
  (с API-ключом или напрямую с паролем панели)
- Исходящий сетевой доступ с сервера WiseCP к серверу панели на API-порт панели

Таблицы в базе не создаются, ничего не устанавливается через Composer, шага сборки нет.

## Установка

Скопируйте папку модуля в вашу установку WiseCP:

```
coremio/
└── modules/
    └── Servers/
        └── DNAHosting/     ← сюда кладётся папка целиком
```

Это вся установка. Дальше запускать нечего — ни миграций, ни прогрева кеша, ни отдельного шага
активации. Модуль появится в списке при следующем открытии экрана добавления сервера.

## Настройка

> Пути меню ниже приведены для англоязычного интерфейса WiseCP.

### Шаг 1 — Добавление сервера

**Products / Services → Hosting/Server → Shared Server Settings → `Add New Shared Server`**

Заполните раздел формы **Server Automation Information**:

| Поле | Что вводить |
|---|---|
| **Server Automation Type** | `DNAHosting` — это имя папки, в списке оно выглядит именно так |
| **IP Address** | Реальный адрес сервера панели; модуль подключается сюда |
| **Username** | Ваше реселлерское имя пользователя в этой панели |
| **Password** | **cPanel:** API-токен WHM. **Plesk:** API-ключ или пароль панели реселлера |
| **Connect with SSL** | Включите |
| **Port** | `2087` для cPanel, `8443` для Plesk |

Поле **Hostname** в верхней части формы — это только подпись для вас: для подключения модуль использует
поле **IP Address**, а не его. В списке ваши серверы отображаются под этой подписью.

### Шаг 2 — Группы серверов (необязательно)

Если серверов несколько, в разделе **Shared Server Settings → `Server Groups`** можно создать группу и
привязать продукт к группе, а не к одному серверу. В окне редактирования группы доступны два типа
распределения:

- **Всегда добавлять на наименее загруженный сервер.**
- **Заполнять один сервер полностью, затем переходить на наименее загруженный.**

Серверы переносятся между списками **Unassigned → Assigned** кнопками `Add` / `Remove`.

> [!IMPORTANT]
> **Держите группу однородной по панели.** Список пакетов в форме продукта берётся с **одного**
> выбранного в этот момент сервера. Если в группе есть и cPanel-, и Plesk-сервер, у выбранного имени
> пакета на другой панели может не оказаться соответствия — и заказ, попавший на этот сервер, завершится
> ошибкой «пакет не найден».

### Шаг 3 — Настройка продукта

**Products / Services → Hosting/Server → Web Hosting Packages** → откройте пакет → вкладка **Module
Settings**.

В разделе **Server Selection** выберите **Single Server** или **Server Group** и отметьте ваш сервер (или
группу) DNAHosting. Как только выбор сделан, модуль отрисовывает собственные поля:

| Поле | Значение |
|---|---|
| **Detected panel** | Панель, которую модуль действительно нашёл на этом сервере — например `cPanel / WHM`. Здесь видно, что определение работает; при проблеме в этой строке появляется текст ошибки. |
| **Package / Plan** | Список пакетов, загружаемый с этого сервера в реальном времени |
| **Automatic Setup** | Включено — заказ разворачивается автоматически; выключено — требуется подтверждение администратора |

Список пакетов зависит от панели:

- **cPanel:** каждый пакет из вывода `listpkgs` на сервере. Если ваши пакеты несут привычный
  реселлерский префикс (например `bakcay328_paket1`), модуль разрешает префикс сам.
- **Plesk:** каждый сервисный план, определённый на сервере.

Выберите пакет, заполните остальную форму как обычно и сохраните. Продукт готов к продаже — при
оформлении заказа полный цикл создания аккаунта отработает на настроенном вами сервере.

## Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| Вызов (чаще всего проверка соединения) падает с `HTTP 403`, либо в тексте ошибки встречается обёртка `cpanelresult` | У реселлерского аккаунта, которому принадлежит токен, нет прав уровня WHM на эту функцию; WHM ответил пользовательским API cPanel вместо WHM API 1 | В WHM откройте **Resellers → Edit Reseller's ACL List** и выдайте реселлеру права, которыми пользуется модуль: список аккаунтов и сводка по аккаунту, создание аккаунта, приостановка, удаление, смена пароля, апгрейд пакета, список пакетов, чтение трафика и создание сессии. Затем перевыпустите токен **под входом от имени этого реселлера** в **WHM → Development → Manage API Tokens** — токен, созданный в интерфейсе cPanel, доступа к WHM не даёт |
| `Plesk (11003)` | API-ключ выпущен для адреса, отличного от IP, с которого подключается WiseCP | Выпустите на сервере Plesk новый ключ для правильного IP либо впишите в поле Password пароль панели |
| `Plesk (1014)` | Plesk отклонил тело запроса — элемент отсутствует или стоит не на том месте для версии XML-API этого сервера | Убедитесь, что используете актуальную версию модуля; в логе модуля видно, к какому именно элементу придрался Plesk |
| Вместо списка пакетов в форме продукта — текст ошибки | Определение панели или запрос пакетов не удался; причина написана в той же строке | Примените одну из строк выше в зависимости от конкретной ошибки в тексте |

Любая другая HTTP-ошибка приходит с текстовой выжимкой из тела ответа панели; голый код состояния —
никогда не вся история. Полный запрос и ответ смотрите в логе модуля.

## Логи

**Tools → Logs → Module Logs**

Каждый отправленный модулем запрос и каждый полученный ответ записываются сюда с меткой имени операции
(например `createacct`, `webspace.add`). Записи ведутся, только пока включена функция **Module Logs**;
этот переключатель находится вверху той же страницы.

> [!NOTE]
> API-токен или пароль сервера, любые пароли аккаунтов, созданные или изменённые модулем, и токены
> SSO-сессий — и в запросе, и в ответе — маскируются символами `***` до записи.
