## نظرة عامة

تُشغّل الوحدة عائلتَي اللوحات من خلال سجل خادم واحد. تُدخل عنوان IP واسم مستخدم الموزّع وبيانات اعتماد
واحدة؛ ثم تستعلم الوحدة من الخادم فعليًا — استدعاء API حقيقي لا تخمين — وتتذكر أي لوحة استجابت.

| | |
|---|---|
| **نوع الوحدة** | وحدة خوادم (Servers) في WiseCP |
| **اسم المجلد** | `DNAHosting` |
| **الإصدار** | 1.0.0 |
| **اللوحات المدعومة** | cPanel/WHM، Plesk |
| **PHP** | 7.4 – 8.4 |
| **لغات الواجهة** | التركية، الإنجليزية (`lang/tr.php`، `lang/en.php`) |

## المتطلبات

- تثبيت **WiseCP** على خادمك الخاص ولديك صلاحية مدير عليه
- PHP مع تفعيل الامتدادين **cURL** و**SimpleXML** (متوفران في كل تثبيت افتراضي تقريبًا)
- إمّا **حساب موزّع cPanel/WHM** (برمز WHM API) أو **حساب موزّع Plesk** (بمفتاح API أو بكلمة مرور
  اللوحة مباشرة)
- نفاذ شبكي صادر من خادم WiseCP إلى خادم اللوحة على منفذ API الخاص باللوحة

لا يُنشأ أي جدول في قاعدة البيانات، ولا يُثبَّت شيء عبر Composer، ولا توجد خطوة بناء.

## التثبيت

انسخ مجلد الوحدة إلى تثبيت WiseCP لديك:

```
coremio/
└── modules/
    └── Servers/
        └── DNAHosting/     ← المجلد بالكامل هنا
```

هذا هو التثبيت كله. لا شيء يُشغَّل بعده — لا ترحيل لقاعدة البيانات، ولا تسخين ذاكرة مؤقتة، ولا خطوة
تفعيل منفصلة. تظهر الوحدة في القائمة في المرة التالية التي تفتح فيها شاشة إضافة خادم.

## الإعداد

> مسارات القوائم أدناه مذكورة حسب واجهة WiseCP الإنجليزية.

### الخطوة 1 — إضافة خادم

**Products / Services → Hosting/Server → Shared Server Settings → `Add New Shared Server`**

املأ قسم **Server Automation Information** في النموذج:

| الحقل | ما يُدخل فيه |
|---|---|
| **Server Automation Type** | `DNAHosting` — وهو اسم المجلد، ويظهر في القائمة كما هو |
| **IP Address** | العنوان الحقيقي لخادم اللوحة؛ الوحدة تتصل به |
| **Username** | اسم مستخدم الموزّع لديك على تلك اللوحة |
| **Password** | **cPanel:** رمز WHM API. **Plesk:** مفتاح API أو كلمة مرور لوحة الموزّع |
| **Connect with SSL** | فعّله |
| **Port** | `2087` لـ cPanel و`8443` لـ Plesk |

حقل **Hostname** في أعلى النموذج ما هو إلا تسمية لك أنت — الوحدة تستخدم حقل **IP Address** للاتصال لا
هذا الحقل. وتظهر خوادمك في شاشة القائمة تحت هذه التسمية.

### الخطوة 2 — مجموعات الخوادم (اختياري)

إن كان لديك أكثر من خادم، يمكنك إنشاء مجموعة من **Shared Server Settings → `Server Groups`** وربط
المنتج بالمجموعة بدل خادم واحد. وتتيح شاشة تحرير المجموعة نوعين للتوزيع:

- **أضِف دائمًا إلى الخادم الأقل امتلاءً.**
- **املأ خادمًا واحدًا بالكامل، ثم انتقل إلى الخادم الأقل امتلاءً.**

تُنقل الخوادم بين قائمتَي **Unassigned → Assigned** بزرَّي `Add` / `Remove`.

> [!IMPORTANT]
> **حافظ على تجانس المجموعة من حيث اللوحة.** قائمة الباقات في نموذج المنتج تُجلب من **خادم واحد** هو
> المحدَّد في تلك اللحظة. وإذا ضمّت المجموعة خادم cPanel وخادم Plesk معًا، فقد لا يكون لاسم الباقة الذي
> اخترته نظير على اللوحة الأخرى، فيفشل الطلب الذي يقع على ذلك الخادم برسالة «الباقة غير موجودة».

### الخطوة 3 — تعريف المنتج

**Products / Services → Hosting/Server → Web Hosting Packages** ← افتح الباقة ← تبويب **Module
Settings**.

تحت **Server Selection** اختر **Single Server** أو **Server Group** ثم حدِّد خادم DNAHosting (أو
مجموعتك). وبمجرد الاختيار ترسم الوحدة حقولها الخاصة:

| الحقل | معناه |
|---|---|
| **Detected panel** | اللوحة التي وجدتها الوحدة فعليًا على ذلك الخادم — مثل `cPanel / WHM`. هنا ترى أن الكشف يعمل؛ وإن كان هناك خلل ظهر نص الخطأ في هذا السطر. |
| **Package / Plan** | قائمة الباقات المجلوبة مباشرة من ذلك الخادم |
| **Automatic Setup** | عند تفعيله يُنشَأ الطلب تلقائيًا؛ وعند إيقافه تلزم موافقة المدير |

تختلف قائمة الباقات باختلاف اللوحة:

- **cPanel:** كل باقة في مخرجات `listpkgs` على الخادم. وإذا كانت باقاتك تحمل بادئة الموزّع المعتادة
  (مثل `bakcay328_paket1`) فالوحدة تحلّ البادئة بنفسها.
- **Plesk:** كل خطة خدمة معرَّفة على الخادم.

اختر الباقة، وأكمل بقية النموذج كالمعتاد ثم احفظ. صار المنتج قابلًا للبيع — وعند تقديم طلب يعمل مسار
إنشاء الحساب كاملًا مقابل الخادم الذي أعددته.

## حل المشكلات

| العَرَض | السبب | الحل |
|---|---|---|
| يفشل استدعاء (غالبًا اختبار الاتصال) بـ `HTTP 403`، أو يظهر في نص الخطأ غلاف `cpanelresult` | حساب الموزّع صاحب الرمز لا يملك صلاحية على مستوى WHM لتلك الدالة؛ فردّ WHM بواجهة **مستخدم** cPanel بدل WHM API 1 | في WHM افتح **Resellers → Edit Reseller's ACL List** وامنح الموزّع الصلاحيات التي تستخدمها الوحدة: سرد الحسابات وملخّص الحساب، وإنشاء الحساب، والتعليق، والإنهاء، وتغيير كلمة المرور، وترقية الباقة، وسرد الباقات، وقراءة الحركة، وإنشاء الجلسة. ثم أعد توليد الرمز **وأنت مسجَّل الدخول بحساب ذلك الموزّع** من **WHM → Development → Manage API Tokens** — فالرمز المولَّد من واجهة cPanel لا يحمل صلاحية WHM |
| `Plesk (11003)` | مفتاح API وُلِّد لعنوان غير العنوان الذي يتصل منه WiseCP | ولّد مفتاحًا جديدًا على خادم Plesk للعنوان الصحيح، أو ضع كلمة مرور اللوحة في حقل Password |
| `Plesk (1014)` | رفض Plesk جسم الطلب — عنصر ناقص أو في موضع خاطئ بالنسبة لإصدار XML-API الذي يتحدثه هذا الخادم | تأكد من أنك تستخدم أحدث إصدار من الوحدة؛ وسجل الوحدة يبيّن العنصر الذي اعترض عليه Plesk بالضبط |
| نص خطأ بدل قائمة الباقات في نموذج المنتج | فشل الكشف أو فشل استدعاء الباقات؛ والسبب مكتوب في السطر نفسه | طبّق أحد الصفوف أعلاه بحسب الخطأ المحدَّد في النص |

كل خطأ HTTP آخر يصلك مع ملخّص نصي مستخرج من جسم استجابة اللوحة؛ فرمز الحالة المجرَّد ليس القصة كاملة
أبدًا. راجع سجل الوحدة للاطلاع على الطلب والاستجابة كاملَين.

## السجلات

**Tools → Logs → Module Logs**

كل طلب ترسله الوحدة وكل استجابة تتلقاها يُكتبان هنا موسومَين باسم العملية (مثل `createacct` و
`webspace.add`). ولا تُحفظ السجلات إلا وميزة **Module Logs** مفعَّلة؛ ومفتاحها في أعلى الصفحة نفسها.

> [!NOTE]
> رمز API أو كلمة مرور الخادم، وأي كلمات مرور حسابات تولّدها الوحدة أو تغيّرها، ورموز جلسات SSO — في
> الطلب والاستجابة معًا — تُقنَّع بـ `***` قبل الكتابة.
